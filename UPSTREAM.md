Test-only formatting: the certificate generator applies `go/format` before
writing or comparing its fixture, so generated files satisfy the CI format check.

The raw encoder follows RFC 9849 section 6.1 and the upstream discussion in
[uTLS PR #432](https://github.com/refraction-networking/utls/pull/432).
The callback cannot replace key-share cryptography. Outer references must retain
outer order and form one contiguous run; ECH itself cannot be compressed.
The fork validates the private SNI, inner marker and TLS 1.3-only versions with at least one usable TLS 1.3 cipher.
Legacy cipher identifiers may remain advertised, as in NSS; they cannot enable
TLS 1.2 negotiation.

Custom ECH resumption appends an engine-owned PSK last in the inner, binds the
exact expanded transcript (including opaque extensions), and preserves HRR ticket
age/hash decisions. The caller chooses omission or randomized public PSK framing;
real ticket identities and binders never appear in the outer. Outer PSK selection
is rejected after ECH rejection. A nil inner policy retains the upstream custom
ECH/PSK rejection. GREASE-only PSK remains on the original path.

`u_ech_psk.go` owns that mechanism; the session controller retains private session
state without overwriting the outer wire model. `u_early_data.go` emits an optional
QUIC early-data extension only after upstream cipher, ALPN and session-event
checks. HRR removes it before CH2. The early traffic transcript uses the inner
when ECH is offered. Browser extension placement and replay policy live in Surf.

For QUIC, the callback may supply a restricted public transport-parameter offer.
The engine retains its complete parameters in the literal inner extension and
rejects compressed references or changes to its real offer. This does not change
QUIC transport semantics. Surf supplies all filtering rules.

ECH rejection verifies the public outer name (RFC 9849 section 6.1.7). Surf owns
authenticated retry policy; the TLS fork only returns the typed rejection error.

For a caller-supplied ECH inner policy, an explicit `Config.KeyLogWriter` also receives the diagnostic label
`UTLS_ECH_INNER_CLIENT_HELLO <outer-random-hex> <expanded-inner-handshake-hex>`.
This is a nonstandard analysis record containing private SNI, PSK identities and
binders, alongside the traffic secrets already exposed by that writer. Keep the
log private. It observes the already-bound transcript immediately before a send
attempt, including HRR CH2, and never marshals or changes handshake state.
Speculative builds emit no record; writer errors stop the send, like ordinary
key-log errors. No diagnostic inner record is emitted without an explicit writer,
without ECH, or for upstream inner construction (which does not expose a bound
raw transcript at this hook). Standard key-log records retain their behavior.
The same writer receives the standard `CLIENT_EARLY_TRAFFIC_SECRET` record
when QUIC enables early writes. It uses the outer wire random, observes the
existing secret, and propagates writer errors before activating that key.

## Updating

Keep the official Git history and the `upstream` remote. Start from a clean
checkout, fetch the desired official revision, and merge it in a separate
worktree. Resolve the hooks in the table above. Normalize only Go module/import
paths to `github.com/enetx/utls`; preserve upstream source links and licenses.
Update `upstream.json` after reviewing and testing the candidate.

```sh
GOWORK=off go mod tidy
GOWORK=off go test -race -count=1 ./...
GOWORK=off go vet ./...
GOWORK=off go test . -run '^$' -fuzz=FuzzCustomECHInnerRaw -fuzztime=10s
```

Also run Surf's full race/coverage suite against the candidate. Its ECH tests
exercise Chrome and Firefox over TCP and QUIC, native Chrome and Firefox TCP/QUIC inner fixtures,
all initially offered key groups, HRR, verified certificates, policy errors and
application bodies. The fixture report distinguishes native decrypted/callback references from
source-derived assertions. Resumption and early-data tests compare verified
client/server states and early traffic secrets, including HRR and ALPN changes.
